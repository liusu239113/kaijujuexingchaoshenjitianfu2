# 《星语奇谭 · 回廊之心》缺陷修复方案

> 对应 GDD：`docs/GDD.md`
> 修复范围：仅修「与 GDD 描述不一致 / 明确不可用」的缺陷，不改动已确认的数值与玩法设计。
> 版本：`versionCode 120` / `versionName 1.2.0`

---

## 0. 结论先行

本次玩家反馈的三类问题，根因**不是三处独立的小毛病，而是三条贯穿全局的主线**：

| 玩家描述 | 真正的根因 | 影响面 |
|---|---|---|
| 「逻辑不通」 | `onTouchEvent` 的按住时长计算顺序错误 + 长按标记从不复位 | **全游戏所有按钮失效** |
| 「UI 重叠」 | 迭塔页整段绘制代码被复制两遍；选人页/主菜单/天赋页写死坐标且不滚动 | 4 个核心页面 |
| 「立绘冲突」 | 资源名拼接错误（宠物、伙伴）＋ 背景插画被不透明图层 100% 盖住 | 全部宠物 + 全部伙伴 + 全部背景 |

其中第 1 条是**致命的**：它会让「按钮点了没反应」被误判成「功能没做」。

## 1. 致命缺陷：全游戏点击失效

### 1.1 现象
任何按钮都要**长按**才有反应；长按过一次之后，**之后所有点击都不再有任何响应**，直到重启游戏。

### 1.2 根因（两处叠加）

**根因 A —— 先把时间戳清零，再拿它算差值**（`ui/GameView.kt` `onTouchEvent`）

```kotlin
MotionEvent.ACTION_UP -> {
    touchDownMs = 0L                                    // 先清零
    ...
    val held = System.currentTimeMillis() - touchDownMs // 再相减 => held ≈ 当前时间戳(1.7e12)
    if (held >= 380L) { handleLongPress(...) }          // 恒为真
    else              { handleTap(...) }                // 永远走不到
}
```

`held` 恒等于「当前 Unix 毫秒时间戳」，必然 `>= 380`，所以**每一次点击都被判成长按**，`handleTap` 是死代码。

**根因 B —— 长按标记只置位、不复位**

`longPressFired` 在 `ACTION_DOWN` 中**从未被复位**。第一次长按后它永久为 `true`，而 `ACTION_UP` 里 `if (dragMoved < 14f && \!longPressFired)` 直接短路 —— **之后所有触摸都不再派发任何事件**。

### 1.3 修复
- `ACTION_UP` 中**先取值再清零**：`val held = System.currentTimeMillis() - touchDownMs` 提到 `touchDownMs = 0L` 之前。
- `ACTION_DOWN` 中补 `longPressFired = false`。

### 1.4 验收标准
- [ ] 任意页面**轻点**按钮立即生效（不再需要长按）。
- [ ] 连续点击 10 次以上，每次都生效。
- [ ] 长按技能/道具仍能弹出详情浮层。
- [ ] 长按一次后再轻点其它按钮，依然生效。

## 2. UI 重叠

### 2.1 迭塔页事件舞台被重复绘制两遍（重度）

**根因**：`ui/ScreenTower.kt` 的 `drawTowerScreen` 中，`drawFloorPath` 被调用 2 次、事件舞台整段被复制 2 次、`drawBottomNav` 被调用 2 次。

后果有三层：
1. 第二遍的 `card(...)` 是不透明的，**直接盖住第一遍已经画好的事件标题、插画与选项文字** —— 这就是玩家看到的「色块压住文字」。
2. `drawBottomNav` 绘制两次 → 底部 6 个导航按钮的 `hit` 矩形**被注册两次** → 点一次触发两遍（音效叠放、状态机被推进两次）。
3. 战斗提示文字 `r.text(c, kindLabel, w/2f, top + h - 150f, ...)` 把 `top`(214) 也算进高度，**画到了屏幕外**，玩家永远看不到「首领战 · 奖励丰厚」。

**修复**：删除重复块，全屏唯一绘制点；`top + h - 150f` 修正为 `h - 150f`。

### 2.2 选人页（轮回编成）职阶网格与「觉醒天赋」按钮重叠

**根因**：`ui/ScreenMenu.kt` `drawSetupScreen` 全程写死 Y 坐标、**没有滚动**。内容总高约 740，而 16:9 机型 `h ≈ 711`：

| 元素 | Y 区间 |
|---|---|
| 职阶网格第 2 行 | 550 – 632 |
| 「觉醒天赋」按钮 | **619 – 677** ← 压住网格 |
| 职阶说明卡 | 664 – 738 ← 直接被挤出屏幕 |

**修复**：内容整体改为 `beginScroll/endScroll` 可滚动区，底部按钮移到滚动区之外固定。

### 2.3 主菜单战绩卡压住底部按钮

**根因**：标题区从 `h * 0.20f` 起算，战绩卡 + 存档卡一路向下，而按钮固定在 `h - 276f` 起。`h = 711` 时存档卡结束于 484，按钮起于 435 → **重叠 49px**。

**修复**：`titleY` 增加自适应上限 `min(h*0.20, (h-276) - 340)`，保证标题区整体落在按钮区之上；存档卡间距 118 → 106。

### 2.4 天赋三选一第 4 张够不到

**根因**：`drawDraftScreen` 无滚动。4 张卡时内容到 770，超过 16:9 的 711 → **第 4 张（大号字体下第 3 张）落在屏幕外且无法触达**。

**修复**：加入 `beginScroll/endScroll`。

### 2.5 面板类（行囊/装备/战技/神格环/道具/伙伴/设定）

| 缺陷 | 根因 | 修复 |
|---|---|---|
| 「一键换装」只露出 6px 却能被点到 | 写死 `bottom-64`，落在裁剪线 `h-136` 以下，且与「关 闭」重叠 | 改为参与列表流布局 |
| 滚到底也看不到「导出存档文本 / 清空存档」 | 画完这一行**漏了 `y +=`**，`panelScrollMax` 少算此行高度 | 补 `y += 54f` |
| 多行技能描述糊成一团 | `r.wrap(..., lineH = 0f)` → 换行不换位置，逐字叠在同一基线 | `lineH` 改 14 |
| 神格点/队伍上限提示浮在滚动内容上 | 写死 `bottom-76`，不随滚动移动 | 改为流式 |
| 伙伴面板标题为空 | `when (panel)` 漏了 `"merc"` 分支 | 补标题 |
| 面板打开时底层屏幕按钮仍可点 | 模态层未屏蔽底层 hit | 见 §4 后续项 |

### 2.6 Canvas 状态泄漏（严重，易被误判为「整个 UI 消失」）

**根因**：`drawPanelOverlay` 中 7 处 `if (p == null) return` **跳过了 `c.restore()`**。

后果：`clipRect` 外泄到同帧后续绘制（含 `drawOverlay` / `drawToast` / 滚动条），部分机型上跨帧残留，表现为**整个界面被永久裁剪**。

**修复**：7 处全部改为 `if (p == null) { c.restore(); return }`。

## 3. 立绘冲突

### 3.1 宠物立绘全部画不出来（重度）

**根因**：资源文件名是 `pet_01.png … pet_12.png`（**无 `pt_` 前缀**），而 `drawPortrait` 统一拼 `pt_` + key：

```kotlin
val bmp = bitmap("pt_" + key)   // 找 pt_pet_01 → 不存在
```

于是 `PetDef.avatar = "pet_01"` 的 12 只宠物**全部走兜底分支**，画成灰色方块 + `★`。

**修复**：`drawPortrait` 增加回退 —— `bitmap("pt_$key") ?: bitmap(key)`。这一改同时覆盖其它命名不一致的资源。

### 3.2 队伍伙伴小图标错配

**根因**：`ArtIcon.companion("cp01")` 拼成 `"ic_cp01"`，而真实资源名是 **`ic_cp_01`（带下划线）** → 永远取不到图，静默回退。

**修复**：`"ic_cp_" + avatarKey.substring(2)`。

### 3.3 背景插画被完全盖住（全部背景资源等于没接）

**根因**：`drawBackground` 先画背景插画，**随后又无条件和上一层完全不透明的 `LinearGradient`**：

```kotlin
c.drawBitmap(bmp, ...)                                  // 画插画
r.fill.shader = LinearGradient(... BG_TOP, BG_BOTTOM ...)
c.drawRect(0f, 0f, w, h, r.fill)                        // 不透明 → 插画被 100% 覆盖
```

6 张背景图（`bg_menu / bg_corridor / bg_battle / bg_result / bg_ending / bg_void`）**一张都看不见**。

**修复**：渐变改为「仅在无插画时铺底」；有插画时插画作为底色、用半透明遮罩压暗以保证文字可读性。

## 4. 玩法逻辑

### 4.1 战技升级是假按钮（「逻辑不通」的另一来源）

**根因**：三处不一致 ——

1. `heroSkillLevel()` 实现是 `p.hero().cooldowns.keys.size.let { 1 }`，**恒返回 1**，参数 `skillId` 根本没用。
2. `RunState` 中**不存在任何技能等级存储**。
3. `panel_learn_` 处理器取了 `sid` 却不使用：没有满级拦截、不写任何状态，**连点会把战技点全部扣光而技能毫无变化**。

**修复**：
- `RunState` 新增 `val skillLevels = HashMap<String, Int>()`。
- `heroSkillLevel` 读取真实等级。
- 升级处理器：`Lv >= 3` 拦截；扣除 1 点；写入 `lv + 1`。
- **接入战斗**：`Battle` 新增 `lvMul(skill)`，`Lv.1 = ×1.0，每级 +12%`，作用于**伤害 / 治疗 / 护盾**三条系数读取路径，使升级真实生效。

### 4.2 设置项不落盘
乐曲/音效开关与音量滑档没有调用 `Save.savePerm`，重启后回退。已补齐。

## 6. 第二轮修复（v1.1.8）

### 6.1 模态层不屏蔽底层点击

**根因**：`hits` 由每帧各控件自行注册，`hitIdAt` 从末尾倒扫。面板/浮层虽然画在最上层，但**只覆盖了卡片范围**，顶栏返回键等区域仍落在底层屏幕注册的 hit 上 —— 点一下会切屏，而 `panel` 还开着，出现「面板停在另一个屏幕上」的错乱状态。

**修复**：7 个模态层（面板 / 商店 / 酒馆 / 战斗结算 / 详情 / 确认框 / 导出）在最开始注册一个全屏 `modal_block`。因为后注册者优先，模态自身的按钮照常生效，底层屏幕则被完全吃掉。

### 6.2 滚出可视区的控件仍可点到（会误扣金币）

**根因**：`beginScroll` 只做 `clipRect`（**只管绘制**），`hit()` 完全不理会裁剪区。背包靠下的格子、装备的「锻铸」按钮滚出屏幕后**看不见却点得到**，会直接扣金币。

**修复**：给 `hit()` 增加裁剪感知 ——
- 新增 `setHitClip/clearHitClip`，由 `beginScroll`/`endScroll` 与面板裁剪自动登记；
- 完全在裁剪区外的控件返回一个落到屏幕外的空矩形（调用方即使把 `.enabled` 设回 `true` 也点不到）；
- 部分可见的控件把矩形**收缩到可见区间**，只有露出来的那部分可点；
- `onDraw` 每帧复位，避免状态跨帧泄漏。

### 6.3 其余布局

| 缺陷 | 根因 | 修复 |
|---|---|---|
| 轮回结算：神格环标签永远压在卡片下边框上 | 基线 `top+208` 超出卡片底边 `top+196` | 卡片加高到 216，基线改 `top+196` |
| 轮回结算：成就列表压住「领取神格点」 | 固定 `take(5)` 且不设上限，`h=711` 时重叠 15px | 按可用高度反推条数，超出显示「还有 N 项」 |
| 战斗结算：4:3 平板奖励文字溢出卡片并压按钮 | 卡片写死 `h-300`、按钮钉死 `h-214` | 先排版算高度，卡片与按钮位置均由内容决定 |
| 详情浮层最后 1–3 行正文被「关 闭」盖住 | 截断阈值只留 16px，按钮却占 58px | 阈值改 74px |
| 确认框长文案压按钮 | 卡片 168 高、按钮在 `top+108`，仅容 2 行 | 卡片 196 高、按钮下移到 `top+132` |
| 招募所未开局时 `endScroll` 被跳过 | early `return` 绕过 `c.restore()`，裁剪状态泄漏 | 先 `endScroll` 再 `return` |

## 7. 第三轮修复（v1.1.9）

### 7.1 主菜单整屏滚动化

**根因**：标题区 + 战绩卡 + 存档卡（从顶部起算）与 7 个按钮（从 `h-276` 起算）是**两套独立锚点**，中间没有约束。屏幕越矮，两者越靠近，直到硬碰撞：

| 屏幕比例 | 设计高度 h | 说明 |
|---|---|---|
| 20:9 / 19.5:9 手机 | 860–889 | 正常 |
| 16:9 手机 | 711 | 上一轮加 `titleY` 上限后正常 |
| 3:2 | 600 | 重叠约 26px |
| 4:3 平板 | 533 | 重叠约 93px |

**修复**：**把按钮组也纳入流式布局**，与标题区同一条 `y` 轴推进。屏幕够高时用留白把按钮推到底部（观感不变），矮屏时按钮自然跟随内容、整屏可滚动 —— 任何高度都不再可能硬碰撞。

配套改动：
- `beginScroll` 增加可选 `bottom` 参数（主菜单需要裁到 `h-12` 而不是默认的 `h-96`）。
- 主菜单所有跳转改用 `goScreen()`：它会重置 `screenScroll`，否则主菜单滚过之后，下一个可滚动屏幕（淬炼/图鉴/成就…）会继承菜单的滚动位置。

### 7.2 字体缩放的系统性修正

**根因**：`Renderer.text()` 把字号乘以 `fontScale`，但**行高是写死的**。选「大」字号后文字变大、行距不变，密集列表开始压叠 —— 等于给了玩家一个「选了反而更糊」的选项。

**修复**（两层）：
1. **`Renderer.wrap()` 行距跟随缩放**：`cy += lineH * fontScale`。这一处覆盖了**全部多行段落文本**，是收益最大的单点修改。
2. **新增 `Renderer.lh(base)`** 并接入共享布局助手 `UiKit.sectionHeader / progressRow / emptyState` —— 成就、图鉴等所有复用这些助手的列表自动获得等比行高。

同时把档位从 `0.88 / 1.00 / 1.14` 收敛为 `0.92 / 1.00 / 1.10`：布局是固定像素行高，1.14 超出它能吸收的上限。收敛后「大字号」成为安全档位。

### 7.3 战技等级写入存档

**根因**：上一轮给 `RunState` 加了 `skillLevels`，但没有扩展 `Save` 的序列化 —— 战技等级只在本轮内存里有效，退出重进就回退到 Lv.1。

**修复**：`saveRun` 增加 `skillLevels` 对象（沿用 `items` 的 `JSONObject` 模式）；`loadRun` 读取，**缺失时按 Lv.1 处理**，因此旧存档可以平滑升级，不需要改 `SAVE_SCHEMA_VERSION`。

### 7.4 删除死代码

`slotGlyph()` 与 `drawEquipRow()` 全项目只有定义、没有任何调用点；且 `drawEquipRow` 与装备面板的内联行是同一套布局的两份实现，留着极易在后续改版中只改一份。已删除。

### 7.5 仍未修复

1. **战斗/迭塔/结局/轮回结算**这几个固定版式屏幕仍不支持滚动（内容本身不长，当前高度下够用）。若将来加大字号或新增内容，需一并滚动化。
2. **存档槽切换**不会重建 `screenScroll`，但已由 `goScreen` 覆盖常见路径。

## 8. 第四轮修复（v1.2.0）—— 移动端体验与信息架构

### 8.1 「轮回淬炼 → 开始新一轮」会静默丢弃存档（玩家反馈：莫名其妙回到创角界面）

**根因**：`tapGrowth` 里 `id == "growth_start" -> screen = Screen.SETUP` ——
「轮回淬炼」页底部那个大按钮**没有任何确认**，一点就把玩家踹回创角界面；
而且它**不清理当前存档**，玩家接着开始新角色时旧远征才被覆盖，进度无声丢失。

**修复**：
- 有进行中的远征时先 `showConfirm`，新增 `newrun` 确认动作，明确告知会放弃第 N 层进度；
- 确认后才 `run = null` + `Save.clearRun()` + 进入创角；
- 无进度或已结算时直接进创角，不多一次点击。
- 顺带修 `growth_back`：原本无条件回标题，现在回 `metaReturn`（从回廊前厅进来的就回前厅）。

### 8.2 战斗页立绘与名字重叠

**根因**：`drawUnitRow` 里名字基线是 `gridTop + 12f + psize`，只比立绘下沿（`gridTop + 8f + psize`）低 **4px**。
11.5px 的中文字身高度约 9px，必然压进立绘里 —— 截图上的「名字糊在人物图上」。

**修复**：基线改为 `gridTop + 8f + psize + 13f`，立绘下沿留 13px 净空。已复核卡片总高（155 ≤ 158）仍在行内。

### 8.3 战技面板：描述被裁剪 + 撞进「升级」按钮

**根因**（两处叠加）：
1. 描述 `r.wrap(..., w - 200f, ...)` 从 x=102 一直铺到 302，而「升级」按钮左沿在 `w - 108f = 292` → **压进按钮 10px**；
2. 卡片高度写死 88，描述基线在 `y+66 / y+80`，第三行 `y+94` **直接落到卡片外**，被下一张卡盖住 —— 截图里「并沉默」后面那截被裁就是这个。

**修复**：新增 `Renderer.wrapClamp()`（最多 N 行、超出补「…」），描述宽度收到 `w - 228f` 避开按钮，卡片加高到 106、行距 114。

### 8.4 底部导航徽章溢出格子

**根因**：徽章固定画在 `x + cw/2 + 12`，而 6 个导航格的宽度只有 `(400-24)/6 = 62.7`，
徽章右沿落到 `x + 65.3` —— **越到隔壁格子上**。

**修复**：改为贴着文字右沿、并用 `coerceAtMost` 夹在本格内。

### 8.5 装备 / 伙伴 / 道具 / 战技 看不了详细属性

**根因**：详情体只有**长按**才触发，轻点没反应；道具面板的行**根本没注册可点区域**。
玩家自然会认为「点不开、看不了属性」。

**修复**：
- 行囊格 / 装备行 / 道具行 / 伙伴卡 / 战技卡**全部改为轻点即开详情**（长按仍可用）；
