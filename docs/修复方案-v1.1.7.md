# 《星语奇谭 · 回廊之心》v1.1.7 缺陷修复方案

> 对应 GDD：`docs/GDD.md`
> 修复范围：仅修「与 GDD 描述不一致 / 明确不可用」的缺陷，不改动已确认的数值与玩法设计。
> 版本：`versionCode 117` / `versionName 1.1.7`

---

## 0. 结论先行

本次玩家反馈的三类问题，根因**不是三处独立的小毛病，而是三条贯穿全局的主线**：

| 玩家描述 | 真正的根因 | 影响面 |
|---|---|---|
| 「逻辑不通」 | `onTouchEvent` 的按住时长计算顺序错误 + 长按标记从不复位 | **全游戏所有按钮失效** |
| 「UI 重叠」 | 迭塔页整段绘制代码被复制两遍；选人页/主菜单/天赋页写死坐标且不滚动 | 4 个核心页面 |
| 「立绘冲突」 | 资源名拼接错误（宠物、伙伴）＋ 背景插画被不透明图层 100% 盖住 | 全部宠物 + 全部伙伴 + 全部背景 |

其中第 1 条是**致命的**：它会让「按钮点了没反应」被误判成「功能没做」。

## 1. 致命缺陷：全游戏点击失效

### 1.1 现象
任何按钮都要**长按**才有反应；长按过一次之后，**之后所有点击都不再有任何响应**，直到重启游戏。

### 1.2 根因（两处叠加）

**根因 A —— 先把时间戳清零，再拿它算差值**（`ui/GameView.kt` `onTouchEvent`）

```kotlin
MotionEvent.ACTION_UP -> {
    touchDownMs = 0L                                    // 先清零
    ...
    val held = System.currentTimeMillis() - touchDownMs // 再相减 => held ≈ 当前时间戳(1.7e12)
    if (held >= 380L) { handleLongPress(...) }          // 恒为真
    else              { handleTap(...) }                // 永远走不到
}
```

`held` 恒等于「当前 Unix 毫秒时间戳」，必然 `>= 380`，所以**每一次点击都被判成长按**，`handleTap` 是死代码。

**根因 B —— 长按标记只置位、不复位**

`longPressFired` 在 `ACTION_DOWN` 中**从未被复位**。第一次长按后它永久为 `true`，而 `ACTION_UP` 里 `if (dragMoved < 14f && \!longPressFired)` 直接短路 —— **之后所有触摸都不再派发任何事件**。

### 1.3 修复
- `ACTION_UP` 中**先取值再清零**：`val held = System.currentTimeMillis() - touchDownMs` 提到 `touchDownMs = 0L` 之前。
- `ACTION_DOWN` 中补 `longPressFired = false`。

### 1.4 验收标准
- [ ] 任意页面**轻点**按钮立即生效（不再需要长按）。
- [ ] 连续点击 10 次以上，每次都生效。
- [ ] 长按技能/道具仍能弹出详情浮层。
- [ ] 长按一次后再轻点其它按钮，依然生效。

## 2. UI 重叠

### 2.1 迭塔页事件舞台被重复绘制两遍（重度）

**根因**：`ui/ScreenTower.kt` 的 `drawTowerScreen` 中，`drawFloorPath` 被调用 2 次、事件舞台整段被复制 2 次、`drawBottomNav` 被调用 2 次。

后果有三层：
1. 第二遍的 `card(...)` 是不透明的，**直接盖住第一遍已经画好的事件标题、插画与选项文字** —— 这就是玩家看到的「色块压住文字」。
2. `drawBottomNav` 绘制两次 → 底部 6 个导航按钮的 `hit` 矩形**被注册两次** → 点一次触发两遍（音效叠放、状态机被推进两次）。
3. 战斗提示文字 `r.text(c, kindLabel, w/2f, top + h - 150f, ...)` 把 `top`(214) 也算进高度，**画到了屏幕外**，玩家永远看不到「首领战 · 奖励丰厚」。

**修复**：删除重复块，全屏唯一绘制点；`top + h - 150f` 修正为 `h - 150f`。

### 2.2 选人页（轮回编成）职阶网格与「觉醒天赋」按钮重叠

**根因**：`ui/ScreenMenu.kt` `drawSetupScreen` 全程写死 Y 坐标、**没有滚动**。内容总高约 740，而 16:9 机型 `h ≈ 711`：

| 元素 | Y 区间 |
|---|---|
| 职阶网格第 2 行 | 550 – 632 |
| 「觉醒天赋」按钮 | **619 – 677** ← 压住网格 |
| 职阶说明卡 | 664 – 738 ← 直接被挤出屏幕 |

**修复**：内容整体改为 `beginScroll/endScroll` 可滚动区，底部按钮移到滚动区之外固定。

### 2.3 主菜单战绩卡压住底部按钮

**根因**：标题区从 `h * 0.20f` 起算，战绩卡 + 存档卡一路向下，而按钮固定在 `h - 276f` 起。`h = 711` 时存档卡结束于 484，按钮起于 435 → **重叠 49px**。

**修复**：`titleY` 增加自适应上限 `min(h*0.20, (h-276) - 340)`，保证标题区整体落在按钮区之上；存档卡间距 118 → 106。

### 2.4 天赋三选一第 4 张够不到

**根因**：`drawDraftScreen` 无滚动。4 张卡时内容到 770，超过 16:9 的 711 → **第 4 张（大号字体下第 3 张）落在屏幕外且无法触达**。

**修复**：加入 `beginScroll/endScroll`。

### 2.5 面板类（行囊/装备/战技/神格环/道具/伙伴/设定）

| 缺陷 | 根因 | 修复 |
|---|---|---|
| 「一键换装」只露出 6px 却能被点到 | 写死 `bottom-64`，落在裁剪线 `h-136` 以下，且与「关 闭」重叠 | 改为参与列表流布局 |
| 滚到底也看不到「导出存档文本 / 清空存档」 | 画完这一行**漏了 `y +=`**，`panelScrollMax` 少算此行高度 | 补 `y += 54f` |
| 多行技能描述糊成一团 | `r.wrap(..., lineH = 0f)` → 换行不换位置，逐字叠在同一基线 | `lineH` 改 14 |
| 神格点/队伍上限提示浮在滚动内容上 | 写死 `bottom-76`，不随滚动移动 | 改为流式 |
| 伙伴面板标题为空 | `when (panel)` 漏了 `"merc"` 分支 | 补标题 |
| 面板打开时底层屏幕按钮仍可点 | 模态层未屏蔽底层 hit | 见 §4 后续项 |

### 2.6 Canvas 状态泄漏（严重，易被误判为「整个 UI 消失」）

**根因**：`drawPanelOverlay` 中 7 处 `if (p == null) return` **跳过了 `c.restore()`**。

后果：`clipRect` 外泄到同帧后续绘制（含 `drawOverlay` / `drawToast` / 滚动条），部分机型上跨帧残留，表现为**整个界面被永久裁剪**。

**修复**：7 处全部改为 `if (p == null) { c.restore(); return }`。

## 3. 立绘冲突

### 3.1 宠物立绘全部画不出来（重度）

**根因**：资源文件名是 `pet_01.png … pet_12.png`（**无 `pt_` 前缀**），而 `drawPortrait` 统一拼 `pt_` + key：

```kotlin
val bmp = bitmap("pt_" + key)   // 找 pt_pet_01 → 不存在
```

于是 `PetDef.avatar = "pet_01"` 的 12 只宠物**全部走兜底分支**，画成灰色方块 + `★`。

**修复**：`drawPortrait` 增加回退 —— `bitmap("pt_$key") ?: bitmap(key)`。这一改同时覆盖其它命名不一致的资源。

### 3.2 队伍伙伴小图标错配

**根因**：`ArtIcon.companion("cp01")` 拼成 `"ic_cp01"`，而真实资源名是 **`ic_cp_01`（带下划线）** → 永远取不到图，静默回退。

**修复**：`"ic_cp_" + avatarKey.substring(2)`。

### 3.3 背景插画被完全盖住（全部背景资源等于没接）

**根因**：`drawBackground` 先画背景插画，**随后又无条件和上一层完全不透明的 `LinearGradient`**：

```kotlin
c.drawBitmap(bmp, ...)                                  // 画插画
r.fill.shader = LinearGradient(... BG_TOP, BG_BOTTOM ...)
c.drawRect(0f, 0f, w, h, r.fill)                        // 不透明 → 插画被 100% 覆盖
```

6 张背景图（`bg_menu / bg_corridor / bg_battle / bg_result / bg_ending / bg_void`）**一张都看不见**。

**修复**：渐变改为「仅在无插画时铺底」；有插画时插画作为底色、用半透明遮罩压暗以保证文字可读性。

## 4. 玩法逻辑

### 4.1 战技升级是假按钮（「逻辑不通」的另一来源）

**根因**：三处不一致 ——

1. `heroSkillLevel()` 实现是 `p.hero().cooldowns.keys.size.let { 1 }`，**恒返回 1**，参数 `skillId` 根本没用。
2. `RunState` 中**不存在任何技能等级存储**。
3. `panel_learn_` 处理器取了 `sid` 却不使用：没有满级拦截、不写任何状态，**连点会把战技点全部扣光而技能毫无变化**。

**修复**：
- `RunState` 新增 `val skillLevels = HashMap<String, Int>()`。
- `heroSkillLevel` 读取真实等级。
- 升级处理器：`Lv >= 3` 拦截；扣除 1 点；写入 `lv + 1`。
- **接入战斗**：`Battle` 新增 `lvMul(skill)`，`Lv.1 = ×1.0，每级 +12%`，作用于**伤害 / 治疗 / 护盾**三条系数读取路径，使升级真实生效。

### 4.2 设置项不落盘
乐曲/音效开关与音量滑档没有调用 `Save.savePerm`，重启后回退。已补齐。

**处理**：从版本库中删除。仓库现在只剩纯 Kotlin/Android 工程结构。

## 6. 本次未修复（已知，列入后续）

按「不扩大改动面」原则留给下一版，均不阻塞核心循环：

1. **模态层未屏蔽底层 hit**：面板/浮层打开时，未被面板卡片覆盖的区域（如顶栏返回键）仍可点击，可能切屏后面板还开着。建议在 `hit()` 内统一做裁剪区过滤。
2. **滚动区外的 hit 仍可点击**：背包靠下的格子、装备锻铸按钮滚出可视区后不可见但可点，有误触风险。
3. **战斗结算浮层在 `h < 630` 的机型上文字压按钮**（4:3 平板）。
4. **主菜单底部 6 个次级按钮**在 `h < 600` 时仍会与战绩卡接近，建议整屏滚动化。
5. **字体缩放下行高不放大**：`fontScale` 只放大文字不改行高，大号字体下所有固定行高布局会按 1.14 倍恶化。
6. **`heroSkillLevel` 未接入保存的存档结构**：技能等级目前是「本轮内」有效，跨存档槽不保留。
